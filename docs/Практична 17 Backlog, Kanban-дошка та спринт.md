# Backlog, Kanban-дошка та спринт

Практична робота №17. Управління програмним проєктом

Проєкт: консольна програма прогнозу погоди. Група ІПЗ-11, ЛНТУ

## 1. Інструмент та налаштування дошки

Використано **GitHub Projects**: репозиторій уже є на GitHub, тому дошку можна пов’язати з ним і не вимагається ще одна система.

**Як створити дошку:**

1. На GitHub відкрити репозиторій і перейти на вкладку **Projects**, натиснути **New project**.
2. Обрати шаблон **Board** (Kanban), назвати проєкт «Weather forecast — Kanban».
3. Налаштувати колонки (поле **Status**): Backlog, To do, In progress, Done. Додати недостаючу колонку можна через меню проєкту (…) → Settings → поле Status.
4. Додати два власних поля: **Пріоритет** (вибір: Must, Should, Could) та **Виконавець** (текст).
5. Додавати картки кнопкою **Add item** у колонці, вводячи назву. У описі картки можна записати задачі чеклістом (рядки з початком «- \[ \]»).

## 3. Колонки дошки та правила

| Колонка | Що тут знаходиться |
| --- | --- |
| Backlog | Усе, що ще не заплановано у спринт |
| To do | Картки поточного спринту, які ще не почато |
| In progress | Картки у роботі; одночасно не більше 2–3 карток (дає зосередженість) |
| Done | Картки, для яких виконано критерії приймання |

Картка переходить у Done лише після того, як працюють її критерії приймання (див. документ «Backlog User Stories»).
