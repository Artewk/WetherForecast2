# Зміна вимог та супровід програмного забезпечення

Практична робота №19. Зміна вимог та супровід програмного забезпечення

Проєкт: консольна програма прогнозу погоди. Група ІПЗ-11, ЛНТУ

## 1. Нова вимога

Після випуску першої версії надійшла нова вимога: користувач має можливість сам обирати, на скільки днів показувати прогноз, замість фіксованих 5 днів.

**US-11.** Як користувач, я хочу вибрати кількість днів прогнозу (від 1 до 7), щоб бачити прогноз на потрібний мені період.

**Пріоритет:** Should. За замовчуванням залишаються 5 днів.

**Критерії приймання:**

- Дано знайдене місто. Коли програма запитує кількість днів і користувач вводить 3, тоді таблиця містить рівно 3 рядки.
- Дано запит кількості днів. Коли користувач натискає Enter без введення, тоді показується прогноз на 5 днів.
- Дано запит кількості днів. Коли користувач вводить значення поза діапазоном 1–7 або текст, тоді програма повідомляє про некоректне значення й показує прогноз на 5 днів.

## 4. Зміни в коді

Зміни робляться в окремій гілці (наприклад, feature/days-choice).

**Крок 1.** У методі Main після вибору міста (після рядка GeoResult place, а разом з US-9 — після блоку вибору зі списку) і перед рядком string lat додати:

```csharp
int days = 5;
Console.Write("Кількість днів (1-7, Enter = 5): ");
string daysText = Console.ReadLine();
if (daysText != null && daysText.Trim() != "")
{
    int parsedDays;
    if (int.TryParse(daysText.Trim(), out parsedDays) && parsedDays >= 1 && parsedDays <= 7)
    {
        days = parsedDays;
    }
    else
    {
        Console.WriteLine("Некоректна кількість днів, використано 5.");
    }
}
```

**Крок 2.** У посиланні на прогноз замінити останній рядок. Було:

```csharp
+ "&forecast_days=5&timezone=auto";
```

Стало:

```csharp
+ "&forecast_days=" + days + "&timezone=auto";
```

Метод PrintForecast не потребує змін: він виводить стільки рядків, скільки даних повернув сервіс.
