# Class Diagram

Практична робота №7. Проєктування структури програмного забезпечення

Проєкт: консольна програма прогнозу погоди. Група ІПЗ-11, ЛНТУ

## 1. Основні компоненти системи та їх відповідальність

| Компонент | Відповідальність |
| --- | --- |
| Program | Ввід і вивід, цикл роботи та команди, запити до API, обробка помилок, робота з історією |
| Models | Класи даних: описують, як виглядають відповіді сервісу та запис історії |
| HttpClient (.NET) | Надсилає запити до Open-Meteo |
| JsonSerializer (.NET) | Перетворює JSON на об’єкти і об’єкти на JSON |
| File (.NET) | Читає й записує файл history.json |
| Open-Meteo | Зовнішній сервіс: координати міст і прогноз |

## 2. Основні сутності та класи

| Клас | Призначення | Властивості |
| --- | --- | --- |
| GeoResponse | Відповідь геокодингу | Results: список знайдених міст |
| GeoResult | Одне знайдене місто | Name, Country, Latitude, Longitude |
| ForecastResponse | Відповідь з прогнозом | Daily: дані по днях |
| DailyData | Дані прогнозу на кілька днів | Time, TempMax, TempMin, Precipitation (списки, по одному значенню на день) |
| HistoryEntry | Один запис історії запитів | City, Country, Date |
| Program | Головний клас програми | методи Main, PrintForecast, LoadHistory, SaveHistory, ShowHistory |

## 4. Зв’язки між класами

- **Композиція GeoResponse → GeoResult (1 до 0..\*).** Відповідь геокодингу містить список знайдених міст. Список може бути порожнім або відсутнім, якщо місто не знайдено.
- **Композиція ForecastResponse → DailyData (1 до 1).** Прогноз містить один блок даних по днях.
- **Залежність Program → Models.** Program отримує з частинами класів моделей, читає їх і створює записи історії.
- **Залежність Program → бібліотеки .NET.** Program використовує HttpClient, JsonSerializer і File.
- **HistoryEntry** не пов’язаний з іншими моделями: їх список тільки зберігається у файлі та показується користувачу.

## 5. Пояснення проєктних рішень

- **Моделі — прості класи даних без логіки.** Вони лише описують, як виглядає відповідь API, тому їх легко зрозуміти й змінювати.
- **Назви властивостей збігаються з ключами JSON.** Для трьох полів, де вони різні, використано атрибут JsonPropertyName, тож розбір JSON не потребує додаткового коду.
- **Списки в DailyData повторюють структуру відповіді API:** по одному значенню на день, а при виводі беруться значення з однаковим індексом.
- **Моделі винесено в окрему папку Models,** щоб відокремити опис даних від логіки.
- **Уся логіка поки що в класі Program,** бо проєкт невеликий. Наступним кроком покращення є окремий клас WeatherService для запитів до API: він відокремив би роботу з мережею від вводу й виводу та спростив би тестування.
